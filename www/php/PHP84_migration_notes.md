# `www/php` の PHP 8.4 対応メモ

対象は `www/php` 配下の PHP ソースです。静的に確認できる互換性問題と、8.4 環境で実行時確認が必要な項目を整理しました。PHP 7.4との両対応を優先し、PHP 8専用の型・構文や属性に依存しない修正を勧めます。

## 先に修正する項目

### 1. 文字列オフセットの旧記法を配列形式に置き換える

- [json.php](json.php#L157) には `$str{0}` / `$str{$i}` 形式の文字列オフセットが多数あります（157〜726行付近）。
- この波括弧形式はPHP 7.4で非推奨、PHP 8.0以降では削除されており、PHP 8.4では構文エラーになります。
- `$str{式}` を `$str[式]` に置き換えます。角括弧形式はPHP 7.4でも使えます。
- このファイルは独自の `Services_JSON` 実装です。可能なら `json_encode()` / `json_decode()` への移行も検討できますが、独自実装の挙動や呼び出し箇所を確認してから行います。

Done json.phpは削除

### 2. PHP 8.2以降の動的プロパティ生成を解消する

- PHP 8.2から、クラスで宣言していないプロパティへの代入は `E_DEPRECATED` になります。PHP 8.4でも同様です。
- 特に [Assignment.php](mark/Assignment.php#L56) は `schema()` のキー（`description`, `criteria`, `files`, `time`, `deadline`）を `$this->{$k}` に設定しますが、クラスで宣言されているのは `id`, `_class`, `name`, `base` だけです。
- [Testcase.php](mark/Testcase.php#L41) は `input`、[Submission.php](mark/Submission.php#L48) は `source` / `output` / `files` などを動的に設定する経路があります。各クラスのスキーマ項目をプロパティとして宣言してください。
- [LogCluster.php](log/LogCluster.php#L14) の `LogElem` はJSONのキーを無制限にプロパティ化し、`LogCluster` も `class`, `user`, `filename`, `lang`, `time`, `code`, `result`, `detail`, `raws` 等を動的に保持します。ログ形式に合わせて宣言するか、可変データを配列/`stdClass` に保持してください。
- 同パターンの `$this->{$k}=...` / `$this->name=...` が他にもあるため、全クラスを検索して宣言漏れを確認してください。`#[AllowDynamicProperties]` はPHP 7.4との互換性を考えると第一選択にせず、明示的なプロパティ宣言を推奨します。

### 3. エラーを即時終了させるハンドラを調整する

- [ErrorHandler.php](ErrorHandler.php#L20) は `set_error_handler()` でほぼ全エラーを受け取り、[34行](ErrorHandler.php#L34) で `die()` します。
- そのため、上記の非推奨警告を残したままでは単なるログでは済まず、該当リクエストがHTTP 500で終了します。動的プロパティ等を直した後も、8.4で出る `E_DEPRECATED` を含めて確認してください。
- ハンドラ側で `error_reporting()` に含まれないレベルや、運用上無視するレベルをどう扱うかを明示してください。非推奨を一括無視する設定だけで移行完了としないでください。

## 移行時に全体確認する項目

### 4. 廃止済み関数・構文をもう一度全ソース検索する

今回の検索では、`mysql_*`, `each()`, `create_function()`, `ereg*`, `split()`, `mcrypt_*`, `__autoload()` などのPHP廃止API利用は `www/php` のPHPコードで確認できませんでした（`json.php` の `{}` オフセットは該当）。依存ファイルやPHP外から読み込まれるコードも含め、移行前に再検索してください。

### 5. PHP 8系の警告・型エラーを実行経路ごとに洗い出す

- 未定義の配列キー、`null` を想定していない内部関数への引数、空データ時の `count()`、不正な型の比較/演算などは、PHP 8で警告や `TypeError` になる場合があります。`$_GET` / `$_POST` / DB結果を直接読む箇所が多いため、入力欠落や空データの経路を確認してください。
- DB層 [pdo.php](data/pdo.php) と [BAClass.php](user/BAClass.php) を含め、PDOドライバ、DBの戻り値、例外モードなどの実行環境も確認してください。
- PHP 8.4で、開発環境の `E_ALL` を有効にして画面・API・バッチ・WebSocket等の代表的な処理を動かし、警告と非推奨を潰します。`ErrorHandler.php` がエラー表示を上書きするため、サーバーログも確認してください。

## 7.4との両対応方針

- オフセットは `[]` に統一し、動的プロパティは通常のプロパティ宣言で解消する。
- 8.0以降専用のunion型、属性による回避策、名前付き引数などは使わず、必要なら7.4でも解釈できる書き方にする。
- PHP 7.4と8.4の両方で構文チェックし、アプリの代表的な機能を同じDB/拡張構成で確認する。CLIの構文チェックだけでは実行時の型・警告問題は検出できません。

## 優先順位

1. `json.php` の文字列オフセット記法を修正（8.4での起動阻害）。
2. `Assignment`, `Testcase`, `Submission`, `LogElem`, `LogCluster` 等の動的プロパティを解消（8.2+の非推奨とエラーハンドラによる500化）。
3. PHP 8.4で全経路を動かして警告・型エラーを洗い出し、7.4でも構文と主要機能を確認。

この文書は静的なコード調査に基づく一覧です。PHP 8.4上での実行確認や全プロジェクトの依存関係確認はまだ行っていません。
